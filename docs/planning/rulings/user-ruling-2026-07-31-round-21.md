3. **V3-AIP-83の全面リネーム(既存97ファイル+import修正)の工数見積もりは存在しない**(§5項番1)。着手前に別途見積もりが必要。
4. **H1-1のみhold=true維持・H1-2/H1-3はhold=false解除という区別は記録役の解釈である**(§5-1)。ユーザーの逐語は3件まとめて「実装していいよ」であり、この区別自体をユーザーが個別確認した事実ではない。

## 9. 判断が要った箇所(実際に混ざった判断)

1. **H1-1(V3-AUT-42)のみhold=trueを維持し、H1-2/H1-3(V3-GOV-31/V3-UIX-39)はhold=falseに解除したこと**(§5-1)。3件とも回答は同一の「実装していいよ」だが、各カードのifYes文面の違い(H1-1のみR1ゲート残置を明記)に基づき記録役が区別した。
2. **AIP83-1・TSC-1・MD-1をいずれも特定のV3要件IDへの`req_status`/`wave`変更としてではなく、`ruling_note`追記または記録のみの扱いとしたこと**。3件とも「既存の確定済み要件の実装方針・運用方針」に関する判断であり、要件本文の是非を問うものではないと判断した。
3. **V3-FND-30のstatement訂正で、元の「v1スコープ外」文言をどこまで残すかの判断**。全文を残した上で末尾に訂正段落を追記する形を取り、元文言の削除は行わなかった(発注書の明示指示どおり)。
4. **thinkgov 4件(TG-1〜TG-4)をいずれも「現状維持の確認」としてregistry側に軽微なruling_note追記のみで処理し、req_status/wave/statementの実質変更を行わなかったこと**。lane-thinkのrecommend(いずれも案A=現状維持)がそのまま○で承認された結果であり、記録役の追加判断は最小限に留めた。
5. **statement書き換え編集での`id`フィールド欠落を自己検出し、同一ラウンド内で修正したこと**(§7)。検算を省略していればこの事故は最終報告まで見過ごされていた可能性がある。
